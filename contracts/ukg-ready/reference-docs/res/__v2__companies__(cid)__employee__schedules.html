Schedules

GET

Fetch Schedule items for a single user. Employee can be specified by one of the parameters - `employee:system_id`, `employee:external_id`, `employee:username`, `username`. Employee can be specified by filter parameter as well. Company Id is specified in the path (URI) parameter. Date range is required, and must not exceed 31 days. Predicted Schedule taken from Employee Work Schedule Profile is displayed in the response `predicted:true`, if GET request is sent for future dates with empty Schedule. Schedules GET endpoint is supported only for companies with TLM functionality (TLM Lite1/2 are not supported).

Parameters

Path Parameters
  • cid
    string
    required
    Company should be referenced via company id or company unique id or company short name using `|short_name` or `!short_name` format.
Query Parameters
  • employee:system_id
    integer
    System id of employee
  • employee:external_id
    string
    External id of employee
  • employee:username
    string
    Employee user name
  • username
    string
    Shortcut for `employee:username` parameter
  • fromDate
    string
    required
    Date Range Start date
  • toDate
    string
    required
    Date Range End date

Responses

Contains Schedules info for specified user for specified period. While using filter in case of multiple errors return 200 code is used as well.

Returned in case invalid date ranges, company or employee references are provided.

Returned in case when got no access to company, user or functionality.

Returned in case the `Accept` header contains media type unsupported by end point

Returned in the event an internal server error occurred while processing the request.

Returned in the event that the call limit is exceeded. The application will be unavailable for subsequent calls for the duration specified by the X-CallLimit-TimeToWait header.

Endpoint to update employees' schedule on specified date range. All data will be replaced with new one on specified date range. Date range is required, and must not exceed 31 days. shift_num is not required. By default it will be set to 1. 1_005 error can be returned if json or xml has incorrect structure or contains unsupported attributes.

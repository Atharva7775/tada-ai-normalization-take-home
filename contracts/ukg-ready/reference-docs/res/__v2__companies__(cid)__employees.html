Employees

GET

Retrieves basic information about the employees a user has permission to view, along with links to operations that provide detailed information about each employee. The Employee operations use a separate security profile item to control access rights, located in the company security profile at: 1. `Modules -> REST API Resources -> Employees -> View`. <b>Only the 'REST API RESOURCES' security profile items, in combination with 'manager permissions', are considered by this REST API resource.</b>

  • v2

Parameters

Path Parameters
  • cid
    string
    required
    Company should be referenced via company id or company unique id or company short name using `|short_name` or `!short_name` format.
Query Parameters
  • ein_id
    integer
    The ein id to get the employees if a company has multiple eins. All employees for all eins are returned if not specified. A list of company eins can be fetched using the ein lookup api.
  • terminated
    boolean
    Used to get either only terminated employees or only active employees. All employees are returned if not specified.

POST

Creates a new Employee record. This operation covers the core fields of the employee. To create a full Employee record, additional API calls are required to update related data, such as Pay Information or Demographics. This related data respects default company settings. The Employee operations use a separate security profile item to control access rights, located in the company security profile at: 1. `Modules -> REST API Resources -> Employees -> Edit`. <b>Only the 'REST API RESOURCES' security profile items, in combination with 'manager permissions', are considered by this REST API resource.</b> When creating an Employee, the following fields are not considered if included in the request body: 'Id', 'Status', 'Terminated', 'Links'. Additionally, required field validation is only performed for system fields like 'Firstname' and not for fields marked as required as part of the company configuration. The fields 'bsn', 'social_insurance', 'social_security', and 'national_insurance' are for backward compatibility; the system uses old processing rules if they are included in the request. The new pattern for national identification numbers is represented by the 'national_id_numbers' field. <b>Note</b>: 'national_id_numbers' is ignored if the request contains any of 'bsn', 'social_insurance', 'social_security', or 'national_insurance'.

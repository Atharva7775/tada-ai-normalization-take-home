Multi Pay Statements

POST

Endpoint to create new pay statement for multiple employees in a bulk with provided `payroll(start_date/end_date)` and `ein(id/display_name)` for the given employees, allows to enter complex data entry. Attributes `type` and `batch` are optional parameters. If consumer does not pass `type` and `batch`, the API will read regular paystatment type as default and master batch as default. Currently several pre-defined pay statement types such as `3rd Party Sick`, `Bonus`, `Void`, `Regular`, `Historical` are used for particular payroll. Pay Statement Types provides you with the ability to define the criteria to be used each time a particular Pay Statement Type is utilized during payroll processing. For example, Regular is used for processing a regular payroll, 3rd Party Sick is used for processing the updates of sick pay paid by a third party, and Historical is used for processing historical updates to employee records.

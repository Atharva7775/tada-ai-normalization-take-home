# Submission checklist

Submit a **private repository URL and exact commit SHA**, or a source archive if
the organizer specifies that channel. Do not add collaborators, publish a public
fork, or send provider materials until the organizer confirms recipient access
and distribution permissions. The organizer supplies the deadline and timezone
with the approved pack; seven days means seven calendar days from that handoff.

- [ ] README describes setup, generation, normalization, validation, and tests.
- [ ] Canonical schemas and enums are defined by you, with rationale and versions.
- [ ] Company, employee, and payroll transformations exist for all three providers
      within the approved scope; any omissions are clearly identified.
- [ ] Mapping matrix cites source fields, lookup meanings, units, and uncertainties.
- [ ] Seeded mock generator produces your own synthetic responses from the specs.
- [ ] Generation manifest records seed, generator version, spec checksums, schema
      pointers, lookup versions, and validation result; no actual customer data.
- [ ] Output examples are generated by your implementation and linked to fixtures.
- [ ] Tests cover semantic conversions, relationships, equivalence, and bad inputs.
- [ ] Source artifacts remain unchanged or changes are clearly documented separately.
- [ ] Clean-clone commands work without provider credentials or external services.
- [ ] AI-use log identifies assistance, verification, rejected assumptions, and tools.
- [ ] Submission report records hours, supported scope, limitations, and next steps.
- [ ] Optional 3–5 minute demo or equivalent written walkthrough shows one end-to-end
      scenario and one ambiguous/invalid case. A video is not mandatory.
- [ ] No secrets, real HR/payroll records, unlicensed provider content, or assessor fixtures.

Use [the report template](docs/SUBMISSION_REPORT.md). Share only through the
organizer-approved channel. A starter-only test pass is not a completed submission.
